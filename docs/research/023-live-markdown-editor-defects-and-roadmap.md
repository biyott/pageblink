**root cause 확정**

- **(a) 줄 단위 인라인 파서 (사용자가 보는 결함)**: `parseLiveRuns`가 `\n`마다 `_block`→`_inline(t, pos, e, …)`을 호출(`ml:259-268`, `ml:307`). `_inline`의 닫는 백틱 탐색은 `j < to`(`ml:378`), 강조의 `_closer`도 `to`까지(`ml:318`). 문단을 넘는 인라인 구간은 아예 찾지 않는다. CommonMark는 같은 문단 안에서 줄을 넘는 코드·강조를 허용한다 ⚠️(스펙 미조회). 툴바 `toggleInline`(`ml:640-643`)은 여러 줄 선택에도 그대로 한 쌍으로 감싼다 → 앱이 파서가 못 읽는 입력을 만든다.
- **(b) 펜스 시각**: 개행 문자는 항상 기본 스타일(`ml:271`)이고 `backgroundColor`는 글리프 뒤에만 칠해진다 ⚠️(Flutter 렌더링 일반 동작, 실제 화면 미확인). 따라서 빈 줄·줄 끝은 배경이 끊겨 "한 덩어리 블록"으로 안 보일 수 있다. 줄 단위 `TextSpan`만으로는 전폭 배경 블록을 만들 수 없다.
- **(c) 펜스 상태기계 (파괴적)**: `_fenceRe = [ \t]{0,3}(```|~~~)`가 문자 종류·길이·정보 문자열 없이 접두만 보고 `inFence = !inFence`(`ml:248`, `ml:261-264`).

### 6. 서버 인덱싱·청킹에 미치는 영향

✅ 서버는 노트 본문을 **마크다운 그대로** 저장한다(`document_endpoint.dart` `saveNote` `:70-125`, `body`·`contentHash=sha256(body)`) 그 다음 `_index`(`:309-355`)가 `chunkPages`(`rag/chunker.dart`)로 청크한다. `normalizeText`는 공백·탭 연속을 한 칸으로, 3줄 이상 연속 개행을 2줄로 줄일 뿐 마커(`#`, `**`, `` ` ``, `- [ ]`, `[t](url)`)를 **지우지 않고 그대로 임베딩 입력에 포함**한다. 문단은 빈 줄(`\n\s*\n`)로 나누므로 빈 줄이 있는 펜스 코드는 청크가 갈라진다. 제목 후보는 `_titleFrom`(`:281-289`)이 첫 줄의 앞쪽 `#>-*[]x`와 공백을 걷어낸다(`x`까지 걷어내 `xray` → `ray`가 되는 점은 이 조사 범위 밖 ⚠️ 별도 확인). 따라서 본 개선안은 **라이브 표시만 바꾸고 저장 문자열은 건드리지 않으므로 서버 변경이 필요 없다.** 텍스트가 바뀌는 것은 사용자 의도가 있는 편집뿐이다: Enter 이어쓰기가 넣는 `- `/`1. `, 체크박스 클릭 토글(`[ ]`↔`[x]`), Tab 들여쓰기. 인용 하이라이트(`findQuote`, `ml:230-244`)는 이미 마커 차이를 8단어·5단어 접두로 허용해 새 규칙의 영향이 없다. 마커를 임베딩 전에 제거하는 개선은 재색인이 필요하므로 이번 범위에서 제외하고 별도 조사로 둔다.

| 캐럿·선택 | 정상 | 실험(Ahem 폰트, 수치 ⚠️): 마커 구간 안의 오프셋들이 **같은 x로 붕괴**, 마커 내부로 히트 테스트가 안 됨 → 방향키가 눈에 보이는 변화 없이 "한 칸 소비"하거나 선택 핸들이 겹침 |
| IME | 조합 밑줄 오버레이 이미 검증 `markdown_live_test` | 조합이 활성 줄이면 마커가 다시 나타나 **줄 폭이 변하며 조합 중 레이아웃이 튐** ⚠️ |
| 캐시·성능 | 텍스트·스타일만 키(`ml:140`)라 선택 변화에는 재파싱 없음 | 활성 줄이 선택에 의존 → **캐럿이 움직일 때마다 스팬 재생성·재레이아웃**, 줄바꿈 위치(wrap)도 변동 |
| 글머리·체크 글리프 | 불가 | 마커를 숨기고 그 자리에 글리프를 그리려면 위젯 오버레이가 필요(§아래 중간안) |
| 구현 규모 ⚠️ | 이미 구현, 추가 없음 | L: 컨트롤러가 선택 줄을 알아야 함 + 기하 보정 + 모바일/웹 IME 실기기 검증 ≈ 300줄 + 많은 회귀 테스트 |
| 위험 | 낮음 | **높음** (한글 IME·선택 핸들·웹 입력 위젯) |

**중간안 (⚠️ 미검증)**: 마커는 (a)처럼 투명/흐림으로 두되, `getBoxesForSelection`(미니바가 쓰는 지오메트리 `bar:30-53`)으로 마커 위치를 재서 그 위에 글머리·체크 위젯을 오버레이하는 방식. 텍스트 불변·캐럿 정상이지만 스크롤·줄바꿈 변화 시 위치 동기화와 히트 영역이 숙제. `WidgetSpan`을 `buildTextSpan`에 넣는 방식은 이번에 **실험하지 않아** 가능/불가를 단정하지 않는다(017 §3은 길이 규칙 위반 가능성을 지적 ⚠️).

**추천: (a) 유지** + 마커 스타일링 강화(체크 박스 구간 강조, 글머리 색, 들여쓰기 깊이 색). 이유: 저장 왕복 100%·IME 안정성 유지, 규모 최소. 사용자가 "마커가 보여서 지저분하다"를 명확히 요구하면 그때 (b)는 별도 스파이크(한글 IME 실기기 포함)로.

## 사용자가 결정해야 할 것

1. **링크 열기 UX**: A(Cmd/Ctrl+클릭)+B(컨텍스트 메뉴)를 기본으로 할지, C(캐럿만 있어도 뜨는 칩)·D(편집 대화상자)까지 갈지. 추천: A+B 먼저.
2. **마커 숨김(b)**: 이번 범위에서 하지 않기로(추천) vs 별도 스파이크.
3. **목록 Enter 이어쓰기**: 2단계에 포함할지(IME 실기기 검증 필요). 포함 시 "빈 항목에서 Enter = 목록 종료"까지 같이.
4. **헤딩 버튼 모양**: 현재처럼 드롭다운 유지(+활성 표시)냐, 클릭으로 H1↔본문을 토글하고 레벨은 화살표/단축키로 바꾸는 분할 버튼이냐. 추천: 드롭다운 유지 + 현재 레벨을 아이콘/라벨에 표시.
5. **코드 블록 버튼 추가 여부**, **취소선·번호 목록 버튼 추가 여부**(툴바 폭이 이미 가로 스크롤).
6. **서버**: 마커 제거 후 임베딩은 이번에 안 함(재색인 필요). 별도 조사 여부.

## 미확인 · 리스크

- ⚠️ 모든 렌더링 판단(코드 배경이 빈 줄에서 끊김, 내어쓰기, 취소선·밑줄 모양)은 소스·`TextSpan` 구조에서의 추론이며 실제 데스크톱·웹·모바일 화면은 보지 못했다.
- ⚠️ 한글 IME composing 중 이어쓰기·마커 숨김 동작, Cmd+클릭의 macOS/Chrome 실제 동작, `url_launcher` 웹의 `noopener`, Android 11 `<queries>`는 실기기·브라우저에서 확인해야 한다.
- ⚠️ CommonMark의 세부 규칙(닫는 펜스 조건, 줄을 넘는 코드·강조, 수평선 우선순위)은 이 조사에서 스펙을 조회하지 않고 기억에 의존했다. 구현 전 스펙 0.31.x로 확인.
- ⚠️ `***bold italic***`(규칙 4)의 실제 스타일 결과는 덤프하지 않았다.
- ⚠️ 캐럿 붕괴 수치는 flutter_test의 Ahem 폰트(글자당 16px) 기준이라 정성 판단용이다.
- `flutter pub deps`를 실행했을 때 의존성 해석 메시지가 출력됐으나 `git status`상 변경 없음 ✅.
