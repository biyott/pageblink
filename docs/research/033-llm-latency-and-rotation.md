## A. 입력 길이별 응답 지연 (OpenRouter)

측정 시각: 2026-10-16 KST 11:35 ~ 11:48. 스크립트 `bench.py`, 원자료 `results.jsonl`(1차), `results2.jsonl`(nemotron, max_tokens 1500), `results3.jsonl`(gemma 재시도).
요청 형식은 `openrouter_llm_provider.dart`와 같음(시스템 프롬프트 + `Sources:` 6개 근거 약 5,670자(EVIDENCE+CONTEXT) + 질문, 스트리밍). 이전 대화는 user/assistant 메시지 쌍으로 앞에 붙였고 쌍마다 답변 600~800자. 텍스트는 전부 합성 한국어. 호출마다 내용이 달라 프롬프트 캐시는 쓰이지 않음(cached_tokens 0). 요청에 `usage: {include: true}`를 추가해 비용을 받았고, 유료 모델은 서비스처럼 `data_collection: deny`를 붙임.

### 1. 결과 요약

- google/gemini-3.1-flash-lite(유료): 10회 모두 성공. H가 0에서 16,000자로 늘어도 TTFT는 약 1초대로 거의 그대로.
- nvidia/nemotron-3-super-120b-a12b:free: 추론(reasoning) 모델이라 `max_tokens` 300에서는 300토큰을 전부 추론에 쓰고 답(content)이 한 글자도 안 나옴. 1,500으로 올려도 10회 중 9회가 답 없이 끝남. TTFT는 "첫 추론 토큰"으로만 측정 가능.
- google/gemma-4-26b-a4b-it:free(기본 모델): **측정 실패.** 총 8회 호출이 모두 429("temporarily rate-limited upstream", 상류 공유 한도). 규칙대로 중단했고, 약 9분 뒤 60초 간격으로 2회 더 시도했지만 같은 결과. 요청 간격(4초 이상)이 문제가 아니라 공급자 쪽 혼잡.

### 2. 토큰 환산

gemini 기준 prompt_tokens(근거 약 5,670자 + 시스템 포함 H=0일 때 3,121~3,163토큰).
- 이력 문자 1자 ≈ **0.53 토큰** (H=8,392자 → +4,425토큰, H=16,177자 → +8,550토큰). 즉 **이력 8,000자 ≈ 4,200토큰**, 16,000자 ≈ 8,500토큰.
- nemotron 토크나이저도 비슷(8,297자 → +4,515토큰, 0.54).
- 합성 텍스트는 어휘가 반복적이라 실제 한국어 문서와 비율이 다소 다를 수 있음(대략 0.5~0.7 사이일 것으로 추정, ⚠️ 미확인).

### 3. gemini-3.1-flash-lite (n=2/조건)

| H(문자, 실제) | prompt_tokens | TTFT(초) 값 / 중앙 / 최대 | 전체(초) 값 / 중앙 / 최대 |
|---|---|---|---|
| 0 | 3,163 / 3,121 | 1.19, 0.90 / 1.04 / 1.19 | 1.9, 1.5 / 1.7 / 1.9 |
| 2,000 (2,330·2,106) | 4,369 / 4,300 | 0.92, 0.96 / 0.94 / 0.96 | 1.9, 1.9 / 1.9 / 1.9 |
| 4,000 (4,202·4,317) | 5,380 / 5,405 | 1.08, 0.85 / 0.97 / 1.08 | 1.8, 1.6 / 1.7 / 1.8 |
| 8,000 (8,392·7,733) | 7,566 / 7,228 | 0.89, 1.10 / 1.00 / 1.10 | 1.4, 1.8 / 1.6 / 1.8 |
| 16,000 (16,177·16,170) | 11,711 / 11,677 | 1.25, 1.07 / 1.16 / 1.25 | 2.1, 1.8 / 1.95 / 2.1 |

(출력은 max_tokens 300으로 잘림, 완료 토큰 156~296. 전체 시간은 이 상한에 영향을 받음.)

- H=0 대비 TTFT 중앙값 증가: 2,000 −0.1초, 4,000 −0.1초, 8,000 −0.04초, 16,000 **+0.12초**.
- TTFT 증가 +2초 이내 최대 H: **16,000자 이상**(시험한 최대값까지 전부 통과).
- 전체 완료 15초 이내 최대 H: **16,000자 이상**(최대 2.1초).

### 4. nemotron-3-super-120b-a12b:free (n=2/조건)

TTFT는 첫 "reasoning" 토큰까지의 시간(서비스 코드는 reasoning 델타를 무시하므로 사용자가 보는 첫 글자가 아님). 전체 시간은 1,500토큰 상한까지 추론한 시간.

| H(문자) | prompt_tokens | 첫 토큰 TTFT(초) 값 / 중앙 | 전체(초, 1500토큰 상한) 값 |
|---|---|---|---|
| 0 | 3,213 / 3,183 | 0.65, 0.40 / 0.52 | 28.1, 32.1 |
| 2,000 | 4,356 / 4,476 | 0.69, 0.48 / 0.58 | 60.1, 29.6 |
| 4,000 | 5,315 / 5,279 | 0.81, 0.79 / 0.80 | 24.7, 28.7 |
| 8,000 | 7,713 / 7,733 | 0.94, 0.77 / 0.85 | 45.1, 30.1 |
| 16,000 | 12,007 / 12,178 | 1.19, 1.23 / 1.21 | 26.0, 24.2 |

- 첫 토큰 TTFT는 H에 따라 완만하게 증가(H=0 중앙 0.52초 → 16,000에서 1.21초, +0.69초). 같은 조건 두 값의 차이(≤0.25초)가 16,000의 증가량보다 작아 이 추세는 뚜렷하지만, 2,000~8,000 구간은 노이즈와 구분되지 않음.
- **사용자가 실제로 보는 첫 글자(content)**: 13회(300토큰 3회 + 1,500토큰 10회) 가운데 content가 나온 것은 H=16,000 한 번(20.5초 후, 추론 1,117토큰 뒤)뿐. 나머지는 1,500토큰을 다 추론에 쓰고 24~60초 동안 답이 없었음. 즉 이 모델은 H와 무관하게 첫 답까지 20초 이상 걸리는 경향. "TTFT +2초 이내"는 첫 추론 토큰 기준으로 16,000까지 통과하지만 content 기준 판정은 불가. "전체 15초 이내"는 시험한 모든 H에서 **미달**(24~60초, 모델 특성).
- 전체 시간의 H 추세는 없음. 같은 조건 두 값이 최대 2배 차이(H=2,000: 60.1 vs 29.6초)로 노이즈가 H 효과보다 훨씬 큼.
- max_tokens 300 호출 3회(첫 토큰 0.53~0.87초, 전체 5.7~6.5초, 답 없음)는 `results.jsonl`에 있음.

### 5. gemma-4-26b-a4b-it:free

측정값 없음(위 1절). 호출 시각 11:35~11:48 동안 8회 모두 429. 따라서 "기본 모델에서 이력 8,000자가 괜찮은가"는 이번 측정으로 답할 수 없음. 같은 계열 크기(활성 파라미터 4B)라 gemini와 비슷하거나 더 빠를 것이라는 추정은 근거 없는 추측(⚠️ 미확인).

### 6. 변동성과 한계

- gemini: 같은 조건 두 값의 차이(TTFT 최대 0.35초, 전체 최대 0.4초)가 H 효과(0.1초 안팎)보다 큼. 즉 시험 범위에서 H의 효과는 노이즈 아래이며, "H가 늘어도 느려지지 않는다"가 정확한 표현. 정밀한 증가율은 이 표본(조건당 2회)으로 알 수 없음.
- 대부분 호출이 11:36~11:46 사이 약 10분 안에 몰려 있어 시간대 혼잡 변화는 보지 못함. 순서는 섞었음(seed 고정 셔플).
- 합성 텍스트라 모델 답의 품질(근거 인용 정확도)은 평가하지 않음. 출력 300토큰 상한이라 실제 서비스의 더 긴 답의 전체 시간은 이보다 길 수 있음(서비스는 상한을 두지 않음).
- 무료 모델은 입력과 무관하게 상류 429가 가장 큰 변수로 나타남.

### 7. 권고

1. 이전 대화 문자 예산 기본 8,000자(≈4,200토큰)와 답변당 800자 축약은 **지연 면에서 적절**. gemini 기준 16,000자까지도 TTFT 증가 0.1초 수준이라 지연 때문에 줄일 이유는 없음. 비용도 작음(gemini 입력 약 $0.25/백만 토큰이면 8,000자 이력은 호출당 약 0.001달러).
2. 올릴 근거도 아직 부족: 기본 모델(gemma)을 못 쟀고, 이력이 길수록 답이 이력에 끌려갈 위험 같은 품질 면은 이번에 안 봄. 8,000자 유지를 권하고, 올린다면 12,000자까지만 시험 후 결정.
3. 이력이 지연에 미치는 영향보다 **모델 선택이 훨씬 큼**: nemotron-3-super는 추론 모델이라 H와 무관하게 첫 글자까지 20초 이상 걸릴 수 있음. 서비스 코드는 reasoning 델타를 버리므로 사용자에게는 긴 무응답으로 보임. 카탈로그 설명(`note`)에 느리다는 점 표시나 reasoning 진행 표시를 검토할 만함.
4. 후속 측정 제안: gemma는 한도가 풀리는 시간대(예: 한국 새벽·오전 이른 시간)나 자기 OpenRouter 키 크레딧 확보 후 같은 스크립트로 재측정(`python3 bench.py results4.jsonl 300 google/gemma-4-26b-a4b-it:free`).

### 8. 사용량

- 총 API 호출 31회(성공 23, 429 8회, 그 외 오류 0). 한도 60회 이내. 요청 간격 4.2초 이상, 429 뒤 30초 휴지. gemma는 연속 3회 실패 규칙으로 중단 후 약 9분 뒤 2회 재시도(실패).
- 유료 호출분(gemini 10회) 비용 합계 약 $0.020(응답 `usage.cost` 합, 호출당 약 $0.001~0.003). 무료 모델 호출은 0.
- OpenRouter 키 값은 어디에도 저장하지 않음(환경변수에서 읽기만).

## B. 모델 카탈로그 로테이션 측정 (OpenRouter)

측정 시각: 2026-10-16 KST 11:51 ~ 12:26 (금요일 낮, 한 번에 약 35분). 스크립트 `bench2.py`(측정)·`agg.py`(집계), 원자료 `rotation.jsonl`, 로그 `run_main2.log`·`run_extra.log`·`run_gemma.log`.
요청 형식은 `openrouter_llm_provider.dart`와 동일(시스템 프롬프트 + `Sources:` 6개 근거 + 질문, 스트리밍, 유료 모델만 `provider.data_collection: deny`). 이력 H는 user/assistant 쌍으로 앞에 붙임. 프롬프트는 전부 합성 한국어. 출력 `max_tokens`=600, 요청 간격 5초 이상, 호출마다 100초 상한(상한을 둔 이유는 6절).
지표: (a) 첫 추론 토큰, (b) 첫 본문(content) 글자, (c) 전체 완료, (d) 코드, (e) usage. 아래 표의 시간은 모두 초.

| nemotron-3-ultra-550b | 3/5 | 503 x2 (상류 오류, 즉시 0.6초 만에) | 0.8~0.9 | 14.0, 15.4 / 39.6 | 14.0, 15.4 / 39.6 |
| nemotron-3-super-120b | 4/4(연결), **본문 0/4** | 없음 | 0.4~0.9 | 본문 없음: 600토큰을 전부 추론에 쓰고 종료 (finish=length) | 13.2, 11.3 / 8.9, 12.2 |
| nemotron-3-nano-omni-30b | 1/4 | 502 x1, 100초 무응답 x2 | 0.4~0.7 | 40.1 (H=0 한 번뿐) | 40.1 |
| nemotron-3.5-lightning | **0/4** (+이전에 멈춘 1회) | 100초 동안 바이트 하나 없음 x4 | 없음 | 없음 | 없음 |
| gemma-4-26b-a4b-it | **0/6** | 429 x6 ("temporarily rate-limited upstream") | - | - | - |

- gemini-3.8-flash는 `reasoning.mandatory=true`(끌 수 없음). 600토큰 한도에서 추론이 573~577토큰을 쓰고 본문이 38~46자에서 잘림. 첫 본문 5.2~5.3초는 한도와 무관하게 추론 때문에 생기는 지연.
- nemotron-3-super: 추론 토큰을 600개 쓰고 본문 0자. 서비스는 `max_tokens`를 주지 않으므로 실제로는 계속 추론한 뒤 본문이 나옴. 이전 측정(위 A절)에서 본문 첫 글자까지 20.5초 걸린 사례 1건이 있고 나머지는 1,500토큰 안에서 본문이 안 나옴(⚠️ 이번엔 재측정하지 않음).
- nemotron-3-nano: **`max_tokens` 600을 무시**함(completion 1,930토큰, reasoning 2,340토큰으로 보고). 40초 걸려 본문이 나온 1건 외에는 100초에도 본문이 없었고 연결 오류도 섞임.
- nemotron-3.5-lightning: 연결은 되지만 응답 바이트가 오지 않고 대기만 함. 5회(이전에 멈춘 1회 포함) 모두 같은 증상이라 추론과 무관한 공급자 문제로 보임.
- gemma-4-26b: 본 측정 3회(연속 429로 규칙대로 중단) + 5분 간격 재시도 3회(12:16, 12:21, 12:26) 모두 429. 시간이 지나도 풀리지 않음. 따라서 **이력 H의 영향 등 gemma 속도는 측정 불가**.

### 2. 이력 H=8,000자의 영향

- gemini-3.1-flash-lite: H=0 → 8,000에서 본문 첫 글자 중앙 1.0 → 1.1초로 차이가 노이즈 수준. prompt_tokens는 약 3,130 → 7,200~7,600.
- gemini-3.8-flash: 5.2 → 5.3초, 변화 없음.
- 무료 추론형(추론 켜짐): ultra는 14~15초(H=0) → 39.6초(H=8,000)로 보이지만 표본 1건씩이라 H 효과인지 혼잡인지 구분 불가. super는 첫 추론 토큰이 0.4~0.5 → 0.8~0.9초로 약 +0.4초(이전 측정과 같은 방향).
- 추론 끄기 실험은 H=0에서만 했으므로 "추론을 끈 무료 모델이 H=8,000에서 어떤지"는 **측정하지 못함**.

### 3. 추론 끄기 실험

형식은 OpenRouter 문서(`docs/guides/best-practices/reasoning-tokens`)의 `reasoning` 객체이며 문서에 있는 값만 사용: `effort: "none"`(추론 완전 끔), `enabled: false`. `GET /api/v1/models`에서 모델별 `reasoning` 정보도 확인.

| 모델 | 모델 목록의 지원 정보 | 보낸 값 | 결과 (H=0) |
|---|---|---|---|
| nemotron-3-super | supported_efforts [medium, low, none], default_enabled true | `"reasoning": {"effort": "none"}` | 3/3 성공. 본문 첫 글자 0.5, 0.5, 0.5초 (기본값은 본문 0/4, 9~13초 뒤에도 없음). 전체 4.3, 7.1, 7.8초. reasoning_tokens 0, finish=stop |
| nemotron-3-ultra (실험 외 추가) | supported_efforts [high, medium, none] | `"reasoning": {"effort": "none"}` | 2/2 성공. 본문 0.8, 0.9초 (기본값 14.0, 15.4초). 전체 19.1, 4.4초(답 길이 차이) |
| nemotron-3-nano-omni | `reasoning` 있음, supported_efforts 없음, default_enabled true, mandatory false | `"reasoning": {"enabled": false}` | 5회 중 2회 성공(나머지 3회는 상류 502). 성공분 본문 0.4, 0.5초, 전체 1.4, 2.8초 (기본값 40초 이상). reasoning_tokens 0 |

- 세 모델 모두 지원하고 효과가 매우 큼: 본문 첫 글자가 **10~40초대에서 1초 미만**으로 줄었고 추론 토큰이 0이 됨. 응답 품질(근거 인용 정확도, 답변 내용)은 이번에 평가하지 않음. 합성 문서라 짧은 "찾을 수 없음" 계열 답이 나오는 경우도 있었음.
- 서버 코드 적용: `openrouter_llm_provider.dart`의 요청 JSON에 필드 하나를 추가하면 됨.
  - 모델 목록의 `reasoning.supported_efforts`에 `"none"`이 있으면 `'reasoning': {'effort': 'none'}` (super, ultra, gemini-3.1-flash-lite).
  - `supported_efforts`가 없고 `mandatory`가 false이며 `default_enabled`가 true이면 `'reasoning': {'enabled': false}` (nano).
  - `mandatory: true`(gemini-3.8-flash)는 `none`을 거부하므로 보내지 않음. `default_enabled`가 false인 모델(gemma)도 보낼 필요 없음.
  - 카탈로그 항목마다 `reasoning` 설정을 가진 필드를 두거나, 단순히 무료 nemotron 3종은 항상 끄는 방식이 가장 쉬움. 이 값은 `max_tokens`와 무관하게 동작함.
- 한계: 모델마다 쓸 수 있는 값이 다르므로 지원하지 않는 값을 보내면 400이 날 수 있음(이번에는 보낸 모델이 모두 지원한다고 목록에 나온 값만 보냄, 오류 없음). nano는 `effort: "none"`을 시험하지 않았음.

### 4. 로테이션 순서 제안

기준: 본문 첫 글자 속도와 연결 안정성. 추론은 nemotron 3종에서 끈다는 전제(끄지 않으면 super/ultra/nano는 모두 10초 이상이라 "느림").

1. **nemotron-3-super (추론 끔)**: 전체 7번(base 4 + off 3) 중 연결 오류 0, 추론 끄면 본문 0.5초. 무료 중 가장 안정적.
2. **nemotron-3-ultra (추론 끔)**: 추론 끄면 0.8~0.9초지만 기본 호출 5회 중 503이 2회 나와 상류가 흔들림(오류율 약 30%). 2순위.
3. **nemotron-3-nano-omni (추론 끔)**: 속도는 가장 빠르나(0.4~0.5초) 시도 9회 중 502 4회·100초 무응답 2회로 불안정. 3순위 또는 "불안정" 표시.
4. **google/gemini-3.1-flash-lite (유료, 최후 안전판)**: 4/4 성공, 본문 0.9~1.2초, 호출당 약 $0.001~0.002. 무료가 모두 실패했을 때 쓰는 마지막 수단으로 적합. 비용을 신경 쓰지 않는다면 1순위로 올려도 됨.
5. gemini-3.8-flash(유료): 추론을 끌 수 없어 본문 약 5초. "느림" 표시 대상. 사용자가 고르게 하고 자동 로테이션에서는 제외 권장.

"불안정"으로 표시하거나 로테이션에서 뺄 대상:
- **nemotron-3.5-lightning**: 5회 모두 응답 없음. 표시가 아니라 카탈로그에서 제외 후보.
- **gemma-4-26b-a4b-it**: 상류 429가 이번 측정 6회 + 이전 측정 10회 이상 연속, 35분 동안 풀리지 않음. 기본 모델이라면 교체 필요(⚠️ 속도는 측정 못 함). 로테이션에 두더라도 429는 즉시(0.3~1.6초) 돌아오므로 건너뛰는 비용은 작음.
- 추론을 끄지 않은 nemotron 3종과 gemini-3.8-flash: "느림".

### 5. 첫 글자 타임아웃과 무료 시도 횟수

- **첫 글자 타임아웃 10초**: 데이터와 맞음. 추론을 끈 모델은 첫 글자가 1초 미만이라 여유가 크고(8초나 5초여도 됨, 단 gemini-3.8-flash는 5.2~5.3초라 5초는 부적절), 추론을 켠 super/ultra/nano는 10~40초라 10초에 확실히 끊김. 멈춘 모델(lightning)과 reasoning만 계속 내보내는 모델(nano)은 10초로 걸러낼 수 있음. **주의**: 타이머는 첫 `content` 글자 기준이어야 함. 첫 reasoning 델타는 0.4~0.9초에 와서 "첫 바이트" 기준이면 super/nano의 긴 무응답을 못 잡음. 지금 서비스 코드는 reasoning 델타를 무시하므로 content가 오기 전까지 타이머를 유지하는 구조로 맞는지 확인 필요.
- **무료 시도 2회**: 실패 형태가 대부분 즉시 실패(429·502·503, 0.3~1.6초)이거나 10초 타임아웃이라, 2회면 최악 약 11~21초. 위 순서(super → ultra)라면 두 번 모두 실패할 확률이 낮고(통상 super는 성공), 그 뒤 유료로 넘어가는 구조가 적절. 불안정한 모델(nano, gemma)이 앞 순서에 있으면 시도 횟수가 헛되이 소진되므로 순서가 중요함. 3회로 늘릴 근거는 없음.

### 6. 한계

- 표본이 작음: (모델 x H)당 2회 목표였으나 실패가 많아 성공 표본이 0~2개인 조건이 많음. 중앙값·최대는 참고용이고 통계적 결론이 아님. ultra H=8,000의 39.6초는 1건.
- 시간대: 금요일 낮 한 번(35분)만 측정. 혼잡은 모델·시간대에 따라 크게 달라서 새벽이나 다른 요일에는 달라질 수 있음. 모델·조건 순서는 섞었고 측정 시각은 `rotation.jsonl`의 `kst`에 있음.
- 429·5xx가 결과를 많이 좌우함. 순서가 섞여 있어도 gemma·lightning은 사실상 한 번도 측정하지 못함.
- 합성 텍스트·합성 질문이라 답변 품질과 추론 끄기가 품질에 미치는 영향은 평가하지 않음. 무료 모델 호출에는 프롬프트 수집 가능성이 있어 합성 데이터만 보냄.
- `max_tokens`=600이라 전체 시간은 서비스(상한 없음)보다 짧게 나옴. nano는 상한을 무시함.
- 호출당 100초 상한을 둔 이유: 첫 시도에서 한 호출이 5분 넘게 멈춰 스크립트를 중단했음(기록되지 않은 1회, lightning으로 추정). 이후 100초 상한을 넣어 "무응답"으로 기록.
- gemini-3.1-flash-lite의 "첫 추론" 값은 본문보다 늦게 오는 경우가 있어 지표로 쓰지 않음.

### 7. 호출 수·실패·비용

- 총 호출 40회(기록 39 + 기록 안 된 중단 1) — 상한 45회 이내. 시간 조건: 요청 간격 5초 이상, 429 후 60초 쉬고 재시도(같은 모델 연속 3회 429면 중단, gemma에 적용).
- 실패 18건(기록 39 중): 429 x6(gemma), 502 x4, 503 x2, 100초 무응답 x6(lightning 4, nano 2) + 기록 안 된 1건.
- 성공했으나 본문이 없는 경우: super 기본 4건(추론만 나오고 600토큰에서 종료).
- 유료 비용: gemini-3.1-flash-lite 4회 약 $0.0076, gemini-3.8-flash 2회 약 $0.0124, 합계 **약 $0.020**(응답 `usage.cost` 합). 무료 모델은 0.
- OpenRouter 키 값은 어디에도 저장·출력하지 않음(환경변수에서 읽기만). 저장소 파일은 만들거나 고치지 않았고 서버 실행·커밋도 하지 않음.
