## 맥락

- [ADR 020](020-demo-account-shared-user.md)은 공유 demo 계정 **1개**를 정했다. 샘플 노트는 영어였고, 한국어 UI에서도 영어 노트에 한국어 질문이 뜨는 구조였다.
- 샘플과 질문 예시의 짝은 제목 접두사 문자열 일치였고, 질문은 클라이언트 l10n에 하드코딩돼 있었다 ✅ (research 028).

## 결정

- **demo 계정 2개**: en `demo@pageblink.invalid`(기존 계정 승계), ko `demo-ko@pageblink.invalid`.
- **로그인 시 UI 언어로 자동 선택**: `signIn([locale])`. 인자가 없으면 en, ko 계정 생성에 실패하면 en으로 폴백한다.
- **샘플과 질문 예시를 서버 상수 `SamplePack` 한 곳으로 모은다.** 필드는 `id`, `locale`, `audience`, `notes`, `pdf`, `questions[{text, evidence}]`.
- 질문은 `sampleHints()` API로 클라이언트에 내려 준다.
- `evidence` 문자열이 샘플 본문에 없으면 **단위 테스트가 실패**한다(질문이 답을 못 내는 드리프트 방지).
- 질문 언어는 **샘플 내용 언어**를 따른다.
- DB 테이블·마이그레이션 없음. Ask 일일 상한(50회)은 두 계정이 **전체 공유**한다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 계정 1개 + 언어 태그 | 마이그레이션과 Ask 핫패스 변경이 필요하다 |
| 질문을 클라이언트 l10n에 하드코딩 | 샘플 본문과 질문이 어긋난다(드리프트) |
| DB 테이블에 저장(S3) | research 028: 2~4개 팩 규모에 과하다. 비개발자 편집 요구가 생기면 재검토 |
| JSON 자산(S4) | research 028: S1 대비 얻는 것이 없고, 서버가 런타임에 파일을 읽어야 해 `web/` 번들 경로에 의존한다 |

## 결과 (좋아지는 점 · 감수할 점 · 재검토 조건)

**좋아지는 점**

- 9차 배포 후 양쪽 계정에 문서 4개씩 `ready`, 서로 섞이지 않는다 ✅ (영 id 8~13 대역, 한 14~17 대역).
- 한국어 샘플은 영어와 같은 사실을 담는다. 영어 노트 날짜에는 연도를 명시했다(8차에서 관찰한 환각 대응).
- 샘플·질문의 원천이 하나라 일반 계정 샘플에도 같은 스키마를 쓸 수 있다.

**감수할 점**

- 여전히 계정마다 공유 계정이다(ADR 020의 감수할 점이 그대로 적용).
- 언어가 둘뿐이라 UI 언어가 늘면 `SamplePack`과 계정을 더해야 한다.
- 영어 노트에 한국어로 질문하는 교차 언어 검색은 8차 라이브에서 동작했지만, 이 결정은 그에 의존하지 않는다.

**롤백 주의**

- 단계 2를 revert하면 (⚠️ 단계 정의는 확인 필요) `demo-ko@`로 열려 있던 기존 세션이 **한도 없는 일반 계정**처럼 동작한다. revert할 때는 해당 토큰을 삭제해야 한다.

**재검토 조건**

- 슬롯 고갈·개인정보 노출이 문제가 되면 → `AnonymousIdp`(ADR 020 재검토 조건과 동일).
- 교차 언어 검색이 충분하다고 확인되면 → 질문 언어를 UI 언어 기준으로 확장(스키마를 맵으로).
