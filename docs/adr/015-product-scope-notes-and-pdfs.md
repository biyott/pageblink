## 맥락
지금까지 PageBlink는 "PDF에 질문하는 앱"이었다. 사용자가 범위를 넓혔다: **Google Keep 스타일 노트 앱**에서 마크다운(모바일 친화적인 단순 에디터)으로 노트를 쓰고, PDF도 올릴 수 있으며, **노트와 PDF 전체에 질문**한다. Notion 같은 실시간 동기화와 풍부한 편집은 **나중** 기능이다.

## 결정
- 제품 범위: 마크다운 노트(작성·수정·미리보기) + PDF 업로드. 질문은 둘을 **한 검색 인덱스**에서 함께 찾는다.
- 데이터 모델: `Document.kind`(`'note'` | `'pdf'`, 기본 `'pdf'`) + `Document.body`(노트의 마크다운, PDF는 null). 노트는 **1페이지짜리 문서**로 취급해 기존 청킹·임베딩·ACL 경로를 그대로 쓴다. 저장 때마다 재청킹·재임베딩.
- 인용: `Citation.kind`를 추가. PDF 인용은 뷰어의 해당 페이지로, 노트 인용은 노트 편집 화면(인용 구절 표시)으로 연다.
- 서버 API: `document.saveNote(documentId?, title, body, projectId?)`, `document.get(documentId)` (ACL 확인).
- **보류**: Notion 같은 실시간 동기화·공동 편집, 풍부한 편집(이미지, 라벨·색·고정·보관 등), 노트 버전 기록 → [plan 005](../plan/005-follow-up-spec.md)의 후속 항목.

## 대안과 기각 이유
- PDF 전용 유지: 가볍게 적어 두는 메모를 같이 검색하지 못해 사용 빈도가 낮다.
- 처음부터 Notion식 실시간 협업 편집: 범위가 커서 해커톤 시간 안에 검증하기 어렵다. 단일 사용자 저장 방식으로 먼저 간다.
- 노트용 별도 테이블·검색 경로: 임베딩·검색·ACL 코드가 둘로 갈라진다. `Document.kind`로 한 경로를 공유하는 쪽이 단순하다.

## 결과
- 👍 노트와 PDF를 한 번에 질문, 기존 ACL·인용 파이프라인 재사용
- 👍 모바일에서 바로 메모 → 질문하는 흐름
- 👎 노트는 저장할 때마다 재임베딩 (호출 비용·지연) ⚠️ 측정 안 함
- 👎 편집은 단일 사용자·저장 방식. 동시 편집 충돌 처리 없음
- 👎 노트 인용은 문서의 "1페이지"로 기록되어 노트 내 위치 표시는 구절 배너 수준 (본문 안 하이라이트는 후속)
- 🔁 재검토: 협업 편집을 시작할 때 (Serverpod 스트림 기반 동기화 설계를 별도 ADR로)
