# 023 · 스캔·폼 전용 PDF 복구(OCR)를 제품화하지 않음

| 상태 | 결정일 | 근거 |
|---|---|---|
| 채택 | 2026-10-16 | [research 031](../research/031-pdf-without-text.md) · [research 032](../research/032-local-pdf-recovery.md) · [devlog 012](../devlog/012-releases-10-to-15.md) |

## 맥락

- 글자 층이 없는 PDF(스캔·이미지·폼 입력란 전용)는 앱이 글자를 읽지 못한다. 전부 글자가 없으면 업로드 단계에서 `no_text`로 거절되고(`UploadKind.noText`), 일부 쪽만 비면 그대로 `ready`가 되어 그 쪽은 검색·질문에서 조용히 빠진다 ✅ (research 031 §0, §1.2).
- 요청은 "PDF 카드에 본문이 안 나오는 문제"였다. 조사해 보니 **실제 원인은 글자 인식이 아니라 카드 미리보기 부재**였고, 미리보기(`Document.preview`)로 해결했다 (14차 서버, 15차 표시·검색).
- 그래도 글자 없는 PDF를 읽는 방법이 있는지 두 갈래로 조사했다.

## 조사 결과 (요약)

| 조사 | 방식 | 확인한 것 |
|---|---|---|
| research 031 | 서버가 유료 비전 모델로 쪽별 전사 | 쪽당 약 $0.0007 ✅. 요약만 넣는 방식은 사실 보존이 낮아 **단독으로 기각**. 문서 이미지가 외부로 나가는 동의·고지 문제 |
| research 032 | 로컬: pdf.js 폼 값 읽기 + 브라우저 OCR(Tesseract.js) | 폼 값은 OCR 없이 그대로 복원 ✅. 양호한 스캔 CER 약 3%, 표·나쁜 화질은 약함. 번들 에셋 용량 약 12.7MB. 실제 스캔 파일은 평가하지 못함 ⚠️ |

## 결정

- **스캔·폼 전용 PDF 복구를 제품에 넣지 않는다.** 글자 층이 없는 PDF는 기존 동작(`no_text` 거절·일부 쪽 검색 제외)을 유지한다.
- 코드는 **A안: 일반 제거 커밋**으로 걷어낸다(15차). git 이력은 그대로 둔다. 14차의 복구 모듈과 에셋은 이력에서 찾을 수 있다.
- **서버 쪽 필드는 휴면으로 남긴다.** `DocPage.source`, `PageText.source`(테이블 아님), `Citation.source`(테이블 아님)와 마이그레이션 `20261016062428206-pdf-recovery-and-preview`는 **운영 DB에 이미 적용**됐다. 이 마이그레이션은 `doc_page.source`와 `document.preview` 두 컬럼을 추가하며, `preview`는 카드 미리보기에 계속 쓴다. `source`는 값을 쓰지 않는 휴면 컬럼이다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 이력 다시 쓰기(복구 커밋 삭제) | 원격이 공개이고 운영 DB에 마이그레이션이 이미 적용돼 있어 저장소와 DB의 정합성이 깨진다 |
| 유료 비전 모델로 전사(research 031) | 문서 이미지를 외부로 보내야 한다. 동의 UI·한도·남용 방어가 선결 조건. 사용자 요청의 핵심도 아니었다. **외부 전송 옵션은 보류**(폐기 아님) |
| 로컬 OCR을 제품에 유지(research 032) | 번들 에셋 약 12.7MB, 쪽당 0.5~3.5초와 메모리 부담, 표·나쁜 화질 약함, 한국어 단어 사이 공백 오류. 실제 스캔 파일로 검증하지 못했다 ⚠️ |
| 마이그레이션 되돌리기 | 운영 DB 컬럼 삭제는 위험 대비 이득이 없다. 널 허용 컬럼이라 그대로 두어도 해가 없다 |

## 결과 (좋아지는 점 · 감수할 점 · 재검토 조건)

**좋아지는 점**

- 번들 크기와 클라이언트 복잡도가 줄고, ADR 003(서버는 텍스트만 받는다)이 그대로 유지된다.
- 사용자 요청의 실제 원인(카드 미리보기)은 별도로 해결했다.

**감수할 점**

- 스캔·폼 전용 PDF는 여전히 검색·질문에 쓰이지 않는다(전부 스캔이면 업로드 거절, 일부면 해당 쪽만 제외).
- 14차에는 복구 에셋이 한시적으로 서빙됐다가 15차에 제거된다. 경위는 [devlog 012](../devlog/012-releases-10-to-15.md). OCR 테스트 페이지는 저장소 밖 임시 도구였다.
- `doc_page.source` 컬럼과 `PageText.source`·`Citation.source` 필드가 쓰이지 않는 채 남는다. 지울 때는 새 마이그레이션이 필요하다.

**재검토 조건**

- 스캔 PDF 요구가 생기면 [research 032](../research/032-local-pdf-recovery.md)를 출발점으로 한다. 그때 실제 스캔 파일로 정확도를 먼저 잰다.
