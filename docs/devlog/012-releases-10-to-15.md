### 사건 ① 두 세션이 같은 저장소의 `main`을 동시에 움직였다

| 항목 | 내용 |
|---|---|
| 상황 | 같은 저장소를 쓰는 두 세션이 거의 같은 시간대에 `main`을 앞으로 옮겼다. 한쪽은 접근성 · PDF 미리보기 작업(우리), 다른 쪽은 편집기 H1~H3와 노트별 배경색 |
| 위험 | 우리 작업 트리는 옛 기준 커밋 위에 있었다. 그대로 커밋해 `main`에 올리면 **상대의 노트 색 기능이 삭제될 뻔했다** |
| 해결(병합 절차) | ① 우리 변경을 **기준 커밋 위에 따로 커밋** → ② 새 `main`(`598dc12`) 위에 **병합**(결과 커밋 `b64747f`, 부모는 `598dc12` 하나뿐인 단일 커밋 ✅ git) → ③ 생성 코드 · 마이그레이션 **재생성** → ④ 테스트 → ⑤ **비교-교환**으로 `main` 이동 → ⑥ 작업 트리 동기화 |
| 충돌 처리 | `documents_screen.dart`(색 선택 · 카드 색 · 무지개 래퍼는 유지하고 호버 · 포커스 변경을 안쪽 `InkWell`에 적용), `theme.dart`(`controlEdge` 중복 선언 → 필드 유지), `migration_registry.txt`(우리 미적용 마이그레이션 2개를 버리고 note-color 줄 유지), `note_color_test.dart`(견본 간격을 `closeTo`로 비교) |
| 마이그레이션 | 우리 마이그레이션 2개(`pdf-recovery-source`, `pdf-preview`)는 병합 후 `pdf-recovery-and-preview` 하나로 **새로 만들어** note-color 뒤에 두었다 |

### 앞으로의 규칙 (②)

| 규칙 | 이유 |
|---|---|
| `main`은 **예상값이 일치할 때만** 옮긴다: `git update-ref refs/heads/main NEW OLD` (OLD가 현재 값과 다르면 실패) | 다른 세션이 먼저 옮겼다면 덮어쓰지 않고 멈춘다 |
| `main` 이동 · 배포 **전에 서로 알린다** | 사건 ①은 서로 모른 채 진행돼 생겼다 |
| 배포는 **한 번에 한 세션** | 배포는 서버 · 웹을 한 번에 내보내고 마이그레이션도 같이 적용된다 |
| 마이그레이션은 **병합 후 새로 생성** | 기준 커밋이 다른 두 세션이 만든 마이그레이션은 순서 · 내용이 어긋난다 |

plan 012 §2에 협업 규칙 절로 옮겨 두었다 ([plan 012](../plan/012-session-handoff.md)).

### 사건 ④ 측정 방법 교훈

- **모델 속도는 반드시 실측한다.** 이전 기본 모델(gemma)은 측정한 호출이 **항상 429**였고, 추론 모델은 **본문 전에 오래 무응답**이었다 ([research 033](../research/033-llm-latency-and-rotation.md)).
- 첫 글자 기준은 "첫 바이트"가 아니라 **첫 본문(`content`) 글자**여야 한다. 추론 델타는 0.4~0.9초에 와서 긴 무응답을 가린다.
- 표본이 작고 한 시간대 측정이라 수치는 참고용이다. 답변 품질은 평가하지 않았다. gemma 한도가 풀리면 재측정한다.
- 결과는 [ADR 024](../adr/024-ask-model-default-reasoning-off-paid-fallback.md)로 남겼다.

### 사건 ⑤ 라이브 확인 요령

- **대화 기록 API는 방문자 키로 확인한다.** demo 계정은 공유 계정이라, 클라이언트가 브라우저별 임의 키(`visitorKey`, 서버는 해시만 저장)를 보내 대화를 구분한다. 라이브에서 `restore` · `open` · `hide`를 부를 때도 같은 키를 보내야 같은 대화가 보인다 ✅ (`ask_history_endpoint.dart`, `visitor_key.dart`).
- **질문 횟수 상한은 전역 공유**다: Ask 일일 상한은 두 demo 계정이 합쳐 쓴다 ([ADR 022](../adr/022-per-locale-demo-accounts-sample-pack.md)). 라이브 확인으로 소모하면 방문자의 상한이 줄어든다.
- 모든 모델이 실패하면 "답변 모델이 일시적으로 바쁩니다" 문구가 나온다 (ADR 024).

## 문제와 해결
- 두 세션의 동시 `main` 이동 → 병합 + 비교-교환 규칙 (사건 ①).
