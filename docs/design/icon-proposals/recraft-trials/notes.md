# Recraft V4.1 Vector 앱 아이콘 시험 생성 노트

작성 2026-10-15 (KST). 코드·git은 건드리지 않았다. ✅ = 직접 확인 / ⚠️ = 미확인·추정.
비교 대상은 손으로 쓴 1차 시안 P1(`../app-icon/p1-folded-page/`). 비교판은 `overview.png`.

## 1. 호출 방식 (✅ 확인)

| 항목 | 값 |
|---|---|
| 모델 | `recraft/recraft-v4.1-vector` (`/api/v1/models?output_modalities=image` 응답에 존재, 59개 이미지 모델 중 recraft 계열 16개) |
| 엔드포인트 | **chat/completions가 아니라 전용 Image API** `POST https://openrouter.ai/api/v1/images` (docs: `/docs/guides/overview/multimodal/image-generation`) |
| 요청 | `{"model", "prompt", "aspect_ratio":"1:1", "output_format":"svg", "n":1}` |
| 지원 파라미터 | `/api/v1/images/models/recraft/recraft-v4.1-vector/endpoints`: `aspect_ratio`(1:1, 4:3, 3:4, 16:9, 9:16, auto), `output_format`(svg만), `n`(1~6), `input_references`(0~1장), 패스스루 `style`/`controls`/`text_layout`. **seed 없음**, 스트리밍 없음 |
| 응답 | `data[0].b64_json` = base64 SVG 문자열, `data[0].media_type` = `image/svg+xml`. base64 디코딩해서 `.svg`로 저장 |
| 가격 | 모델 페이지·endpoints API 모두 **$0.08/image** |
| 실비용 | 응답 `usage.cost` = **0.08 × 4장 = $0.32** (`completion_tokens` 4175, `cost_details.upstream_inference_cost` 0.08). 응답에 generation id가 없어 `/generation` 조회로 교차 확인은 못 했다(⚠️), 대시보드 잔액 대조도 안 함 |

- ⚠️ chat/completions 경로(모델 페이지가 언급하는 `image_config.rgb_colors`/`background_rgb_color`)는 호출하지 않았다.
- ⚠️ `controls`(팔레트 고정으로 추정)·`style` 패스스루는 시험하지 않았다.
- 실패: 첫 호출은 python `urllib`의 SSL 인증서 오류(로컬 환경)로 요청이 나가기 전에 실패해 비용 0. `curl`로 교체 후 4건 모두 첫 시도에 HTTP 200. 폴백 모델은 쓰지 않았다.
- 생성 소요 시간은 측정하지 않았다(모델 페이지 기재 "약 10초"는 미검증).

## 2. 생성 결과 (4장)

공통 스타일 문장(프롬프트 원문은 `rN.prompt.txt`): "App icon, flat vector style, solid purple #7C5CFF and white only, square 1024x1024 composition, simple geometric shapes, no text, no letters, no gradients, no shadows, no lightning bolt, large bold forms that stay readable at 16px, centered, full-bleed purple #7C5CFF background."

| ID | 의도 | 파일 |
|---|---|---|
| R1 | 페이지 + 하이라이트 줄 끝의 4꼭지 별 | `r1.svg/png`, `r1.prompt.txt`, `r1.response.json` |
| R2 | 페이지 안 굵은 세로 커서 막대 | `r2.*` |
| R3 | 대괄호 `[ ]` 안에 점(인용) | `r3.*` |
| R4 | 접힌 모서리를 크게 강조한 흰 페이지 | `r4.*` |

`raster/rN-{16,32,48}.png`는 `rsvg-convert`로 해당 크기에서 직접 렌더한 것. `response.json`은 b64 본문을 뺀 메타(usage·요청)다.

## 3. SVG 품질 (✅ 파일 직접 계측)

| | 파일 크기 | 경로 수 | 메타 제외 크기 | 색(`fill`) | 비고 |
|---|---|---|---|---|---|
| R1 | 23,181 B | 9 | ≈5.5 KB | `rgb(108,46,252)`=#6C2EFC, `rgb(254,254,254)` | 흰 면 4 + 보라 줄 4 + 배경 |
| R2 | 18,365 B | 2 | ≈0.7 KB | #6A32FC, #FEFEFE | 배경 + 흰 막대 사각형 |
| R3 | 20,073 B | 4 | ≈2.4 KB | #6822F8, #FFFEFE | 배경 + 대괄호 2 + 점 |
| R4 | 19,513 B | 3 | ≈1.8 KB | #6938F6, #FEFEFE | 배경 + 페이지 + 접힌 삼각형 |
| (참고) P1 | 2,257 B | 3 | — | 그라데이션 타일 | 손으로 작성 |

공통으로 확인된 점:
- **불필요 요소**: 매 파일의 `<metadata>`에 **C2PA 매니페스트(base64 17.7KB)**가 들어 있다(전체의 76~96%). 제거해도 렌더에 영향 없음. 제거 가능 여부를 요청 단계에서 끄는 방법은 못 찾았다(⚠️).
- **캔버스**: `viewBox="0 0 2048 2048"`에 `width/height=1024`, `preserveAspectRatio="none"`. 1024 좌표계가 아니다. 모든 path에 의미 없는 `transform="translate(0,0)"`.
- **배경은 전체 캔버스 path 1개**(`M 0 0 L 2048 0 …`)로 구워져 있다. 투명 전경(적응형)으로 쓰려면 첫 path를 지워야 한다.
- **구조**: `<g>`·`id`·`<title>`·그라데이션·스트로크 없음. 전부 `fill`만 있는 단순 path라 후처리는 쉽다. 단, 직선이어야 할 변이 `C` 베지어(좌표 소수 3자리)로 표현돼 미세하게 흔들리고, 원·모서리 반경이 정규값이 아니다. 숫자를 사람이 고쳐 쓰기엔 불편해서 사실상 **재작도 전제**.
- **팔레트**: 프롬프트에 #7C5CFF를 명시했지만 **모두 #6C2EFC~#6822F8 계열로 더 짙고 채도가 높게** 나왔고 4장 사이에서도 값이 다르다(G 채널 34~56 편차). 흰색은 #FEFEFE. 브랜드 `accent` #6C4CF5와도 맞지 않는다. 후처리로 색 치환이 필요하다.

## 4. 시안별 평가 (overview.png 기준)

| | 컨셉 반영 | 16px | 32/48px | 평가 |
|---|---|---|---|---|
| R1 | 부분. **"하이라이트된 한 줄"은 표현되지 않았고** 줄 5개가 동일한 문서 + 오른쪽에 별. 별이 페이지 오른쪽 변을 오목하게 파고드는 형태는 흥미롭다 | "문서"로는 식별되나 별이 사라짐 | 48px에서 별 식별, 32px에서는 점 | 잘 안 읽히는 디테일(줄 5개)이 많아 앱 아이콘엔 복잡. 글리프가 캔버스 중앙 45%로 작다 |
| R2 | **실패**. 페이지 없이 흰 막대 1개만 나왔다(프롬프트 "페이지 안에" 무시) | 흐린 세로선 | 얇은 세로선 | 아이콘이 아님. 막대가 얇고 캔버스 대비 작다 |
| R3 | 반영됨. 단, 내 프롬프트가 "보라 대괄호/흰 배경"과 "보라 풀블리드 배경"을 동시에 요구해 **모델이 흰 괄호 + 보라 배경으로 해석**했다(프롬프트 설계 문제) | 괄호는 보이나 점이 거의 사라짐 | 가장 깔끔. 괄호 모서리 곡선 양호 | 형태가 가장 단순하고 경로가 적다. 의미("인용")는 설명이 있어야 전달되며 코드/위키링크·뷰파인더로도 읽힌다 |
| R4 | 반영됨. 접힌 코너가 분리된 삼각형으로 표현 | 가장 선명한 "문서" 실루엣 | 선명 | **일반 "파일" 아이콘**(Lucide `file` 류)과 구분이 안 된다. 제품 정체성 없음 |

## 5. 결론

- **앱 아이콘 최종 원본으로는 부적합.** 팔레트 이탈, 비결정성, 변형(다크·적응형·단색) 생성 불가, 프롬프트 불복종 때문에 P1 같은 토큰 기반 손 작성안이 더 낫다.
- **UI 아이콘 세트(24px 그리드, 12개 이상, 선 굵기 일관)에도 부적합.** 스트로크·그리드·반경 제어가 없고 장마다 스타일이 흔들린다. 일관성 도구인 `recraft-v4-styles-vector`(스타일 참조 이미지 필수)는 시험하지 않았다(⚠️).
- **쓸 만한 용도**: 형태 스케치 탐색. R3(대괄호 점)과 R1(별이 파고드는 페이지)은 "손으로 다시 그릴 출발점"으로 가치가 있다. 쓸 때는 `<metadata>` 제거, 배경 path 삭제, 색 치환, 좌표 1024 정규화를 거쳐 재작도한다.
- **다음에 시험해 볼 만한 것(미실행, ⚠️)**: ① `controls`로 팔레트 고정이 되는지, ② `input_references`에 P1 마스터를 넣은 이미지 기반 변형(공식 지원: 1장), ③ 프롬프트를 단일 색 지시로 정리한 재시험(R3 해석 충돌 제거). 비용 예상 장당 $0.08.
- 한계: 4장 1회 시험이라 통계적 결론이 아니다. 모델 이름·가격·파라미터는 2026-10-15 시점 API 응답 기준.
