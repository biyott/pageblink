✅ = 직접 확인 / ⚠️ = 미확인·추정. 이미지 생성 모델은 쓰지 않았고 전부 손으로 쓴 SVG를 `rsvg-convert` 2.62.3으로 렌더했다.

## 0. 클라이언트 피드백과 방향

- 앱 아이콘에서 **번개(⚡)를 뺀다.** 번개는 앱 안의 인용 칩 `⚡n`에만 남긴다.
- 의미는 Note + Blink(출처로 즉시 이동) + RAG(내 노트/PDF에서 근거를 찾아 답함) 중 한두 개만 읽히면 된다.
- 네 꼭지 **반짝 별**을 가장 선호 → V1을 a/b 두 변형으로 그렸다.

## 3. 형태 규칙 (공통)

- **마스터**: 1024×1024 풀블리드·불투명, 글리프 1.2배. **적응형 전경**은 같은 글리프 1.0배(투명).
- **안전 영역(✅ 전경 PNG의 불투명 픽셀 최대 반경을 계산)**: V1a 283.6 / V1b 279.9 / V2 279.9 / V3 278.4 / V4 279.9 — 전부 안전 원 반지름 313 이내(최소 여유 29px). `adaptive-safe-zone-check.png`로도 시각 확인.
- **페이지**: 360×460, 모서리 반경 36(접힌 코너 제외 세 모서리), 접힌 코너(V1a·V2) 100. 1차 P1과 같은 도형이다.
- **반짝 별(V1a/V1b/V3)**: 네 꼭지, 변 4개가 모두 중심 쪽으로 오목한 2차 베지어 `Q` 곡선. 제어점을 중심에서 반지름의 7%만 벗어나게 해 허리를 얇게(허리 ≈ 0.4R). **광학 보정** 두 가지: ① 가로 꼭지를 세로보다 3% 길게(세로 선이 더 길어 보이는 착시 보정), ② 같은 색 6~8px 둥근 스트로크를 더해 작은 크기에서 꼭지가 사라지지 않게 한다.
- **한 아이콘에 별은 하나**. 작은 별을 흩뿌리지 않는다.
- V1b는 별을 페이지 위에 올리지 않고 **별의 윗-오른쪽 오목 곡선을 페이지 외곽선으로 삼았다**(별 중심 = 이전 접힘선의 꼭짓점, 위/오른쪽 꼭지가 페이지 위/오른쪽 변에 닿음). 코너가 별 모양으로 파이므로 오버레이·돌출이 없다.

## 4. 시안

### V1a Sparkle Note — 하이라이트 줄 끝의 반짝 (RAG + Blink)
- **컨셉**: 노트 한 장에서 한 줄이 하이라이트되고 그 끝에 강조 보라 반짝이 앉는다 = "내 노트에서 근거를 찾았다".
- **16px**: **약함~보통**. 16/32px에서 띠 + 별이 오른쪽 화살표(→)처럼 읽힌다. 별 모양은 48px부터 분명하다.
- **약점**: 작은 크기에서 '다음/전달' 화살표로 오독될 수 있고, 줄 3개 + 띠 + 별로 요소가 가장 많다. 16px 전용 단순판이 필요하다(⚠️ 이번에는 만들지 않음).

### V1b Sparkle Fold — 접힌 모서리가 반짝이 됨 (Note + Blink)
- **컨셉**: 접힌 모서리 자체가 반짝 별. 표식 하나로 "노트"와 "깜빡"이 함께 읽힌다.
- **16px**: **좋음**. 우상단이 파인 흰 페이지 + 보라 십자 점이 남아 실루엣이 독특하다. 단 16px에서는 반짝이라기보다 '모서리의 보라 점'이고, 32px부터 반짝으로 확실하다.
- **약점**: 우상단 별은 작은 크기에서 'AI 반짝' 배지처럼 보일 위험이 남는다. 별 외곽 흰 링이 페이지 모서리를 1024 기준 약 11px 넘어간다.

### V2 Cursor Page — 페이지 + 텍스트 커서
- **컨셉**: 페이지 안의 굵은 세로 커서 막대 하나(깜빡이는 캐럿 = Blink = 쓰는 중). 글줄은 커서 앞 한 줄만.
- **16px**: **약함~보통**. 흰 페이지 안의 세로 줄 하나라 커서보다 구분선/페이지로 읽힌다. 32px에서 커서.
- **약점**: RAG·출처 의미가 없고 노트 편집기 아이콘에 가깝다. 다른 텍스트 편집 앱과 혼동.

### V3 Citation Bracket — `[ ✦ ]`
- **컨셉**: 제품의 인용 표기 `[n]` 자체가 로고, 가운데 반짝 하나. 번개 없이 UI 인용과 직결된다.
- **라이트/다크**: 브리프의 "보라 대괄호"를 지키려 라이트는 **파스텔 타일 + 보라 대괄호**, 다크는 다크 타일 + 라벤더 대괄호. (보라 타일 + 흰 대괄호도 가능하며 1차 P1과 더 닮는다.)
- **16px**: **보통~좋음**. `[ ]`는 라이트·다크 모두 또렷하지만 가운데 반짝은 점으로 뭉개진다. 라이트 파스텔 타일은 밝은 배경에서 경계가 약하다.
- **약점**: 노트/PDF 앱이라는 느낌이 약하고 개발 도구·코드 앱(배열 `[ ]`)처럼 보일 수 있다.

### V4 Folded Corner — 크게 접힌 보라 모서리
- **컨셉**: 흰 페이지 + 크게 접힌 보라 모서리 + 안쪽의 점 하나. 가장 단순한 페이지 마크.
- **16px**: 식별은 **좋음**, 개성은 약함. 접힘 실루엣은 남지만 점은 사라져 흔한 문서 아이콘과 구분이 어렵다.
- **약점**: 차별성이 가장 낮고 Blink/RAG 의미를 전달하지 못한다.

## 6. 추천

1. **V1b (1순위)**: 반짝 선호 + 별이 페이지 외곽선 자체라 오버레이 클리셰를 피하고, 16px에서도 가장 안정적으로 식별된다. 다만 16px에서 별은 점 수준이므로 파비콘에서는 '페이지+보라 점'으로 쓰인다.
2. **V3 (2순위, 대안)**: 인용 `[n]`이 UI 어휘와 이어지고 16px에서 괄호 형태가 가장 또렷하다. 노트 앱이라는 느낌은 V1b가 낫다. V1a는 의미가 가장 구체적이지만 작은 크기에서 화살표로 읽혀 앱 아이콘 1순위로는 비추(스토어 큰 이미지·소개용 일러스트로는 적합). V2·V4는 의미·차별성이 부족.

## 7. ⚡ 인용 칩과 아이콘의 역할 분담

- **아이콘 = 제품이 무엇인가**: 노트(페이지) + 반짝(찾아낸 근거). 번개는 쓰지 않는다.
- **UI의 ⚡ 인용 칩 = 지금 무슨 일이 일어나는가**: 답변 안에서 출처로 즉시 이동하는 동작. 번개는 앱 안에서만 보이므로 홈 화면 아이콘과 겹치지 않는다.
- 반짝(아이콘)은 "근거를 찾아 준다", 번개(칩)는 "그 근거로 점프"로 의미가 갈린다. 사이드바 브랜드 마크를 반짝으로 바꿀지는 별도 결정(⚠️ 미정).

## 9. Flutter 구현 메모 (⚠️ 코드 미수정, 계획)

- 앱 아이콘은 `flutter_launcher_icons`(1차 spec 3.1과 동일, README 키 ✅ / 이 저장소에서 실행 ⚠️ 미확인): `image_path`=`master-light.png`, `adaptive_icon_foreground`=`adaptive-foreground.png`, `adaptive_icon_background`=`adaptive-background.png`, `remove_alpha_ios: true`, `web.theme_color: "#6C4CF5"`. V3를 고르면 배경이 파스텔이므로 `web.background_color`/`theme_color`는 `#EDE6FA` 쪽이 맞다.
- 별 마크를 앱 안에서 쓸 때(사이드바 브랜드 마크 등)는 `CustomPainter`로 `Path`를 그린다: 중심 기준 꼭지 4개를 `quadraticBezierTo`(제어점 = 중심에서 ±0.07R)로 이으면 마스터와 같은 곡선이다. 채움 색은 `ColorScheme.primary`(`pb.accent`)라서 라이트/다크가 자동 전환된다(⚠️ 구현 미검증).
- 다크 변형 자산은 OS 선택용이다. iOS 18 다크는 투명 글리프가 필요하므로 선택안 확정 후 `ios-dark-transparent`를 만든다.

## 10. 한계

- 16/32/48 래스터는 `rsvg-convert`가 해당 픽셀로 직접 렌더한 것이다(실제 OS 마스크·홈 화면 보정과 다름). 16px 판정은 그 이미지를 눈으로 확인한 것이다.
