## 1. 결정 요약

| 항목 | 결정 |

## 2. 자동(Auto) 규칙 — 반드시 지킬 것

현재 `Pb.noteColor(id) => notes[(id ?? 0) % notes.length]`다. `notes`를 8개로 늘리면 **모든 기존 자동 노트의 색이 바뀐다.**

- 자동은 계속 `id % 5`, 인덱스 0–4만 쓴다(기존 노트 색 불변). 5–7과 8은 **직접 고른 노트에서만** 나온다.
- `Pb.notes`(5개)는 그대로 둔다(`sign_in_screen.dart`가 `pb.notes[0]`을 쓴다). 새 토큰은 따로 추가한다(§7).

- 인접 파스텔의 구분은 색만이 아니라 이름(캡션·Semantics)이 보조한다.

그라디언트는 1차원 경로라 화면의 모든 점이 이 경로 위 색이다. 경로를 감마 sRGB로 3,001점 샘플링해 각 글자색의 **최솟값**을 구했다.

## 5. 선택기 UI

### 5.1 컨테이너

| 폭 | 컨테이너 | 이유 |
|---|---|---|
| `<600` | `showModalBottomSheet`(`useRootNavigator`, `showDragHandle`, `SafeArea`) | `ask_screen.dart`의 `_pickScope`/`_pickChat`과 같은 분기. 엄지 도달, 격자가 한 화면에 들어옴 |
| `≥600` (태블릿·데스크톱) | **앵커 팝오버**: `MenuAnchor`(또는 커스텀 `PopupMenuEntry`)가 ⋯/팔레트 버튼 아래에 열림(`alignmentOffset` (0, 4)), 폭 288 | 다이얼로그는 과하다. 카드·편집기 옆에서 결과가 바로 보여야 한다 |

- 진입점: ① 편집기 헤더에 팔레트 아이콘 버튼(`LucideIcons.palette`, 36/44 타깃) — 한 번에 열림. ② 카드 ⋯ 메뉴의 항목 `노트 색`. 메뉴 항목은 누르면 메뉴가 닫혀 앵커가 사라지므로, 데스크톱에서는 **⋯ 버튼의 렌더 박스에 팝오버를 앵커**한다(항목 위가 아님). 폰은 시트라 해당 없음.
- 닫기: 바깥 탭·스와이프·`Esc`. 확인/취소 버튼 없음(탭 = 적용).
- 열려 있는 동안 뒤의 카드가 즉시 바뀐다(시안 폰 좌측: 뒤의 카드가 무지개로 바뀌어 있음).

### 5.3 스와치 외형

| 상태 | 외형 |
|---|---|
| 기본 단색 | 지름 40 원, 채움 = 팔레트 색, **1px 테두리** `ink 28%`를 면 위에 블렌드한 값(라이트 `#C0BEBB`, 다크 `#615B61`) |
| 자동(Auto) | 채움 `pb.pdfPaper`(라이트 흰색, 다크 `#2A2620`) + 같은 1px 테두리 + 가운데 **세리프 `A`** 18/w600 `inkMuted`(라이트 7.54, 다크 6.76). 파스텔이 아니라 "종이 + 글자"라 한눈에 다른 종류. "색 없음"을 뜻하는 사선 원은 쓰지 않는다(자동은 색이 *골라진다*는 뜻이라 사선이 틀림) |
| 무지개 | 같은 6정지를 **스윕**: `SweepGradient(colors: [...6정지, 첫색 반복], transform: GradientRotation(-pi/2))`(위에서 시작). 선형 그라디언트는 40dp 원에서 탁해 보인다. 1px 테두리 동일 |
| **선택됨** | 원 안쪽 가장자리 **2px `ink` 링** + 가운데 **체크**(Lucide check 18, 스트로크 2, `ink`). 체크 대비는 모든 스와치에서 라이트 ≥13.14, 다크 ≥9.12 |
| 키보드 포커스 | 기존 `PbFocusRing`(2px `ink`, 간격 2, 바깥). 선택 링(안쪽)과 위치가 달라 겹치지 않는다 |
| 호버(데스크톱) | 48 셀에 `pb.hover` 원 배경(ink 6%), 툴팁 400ms 뒤 |
| 눌림 | `pb.press`(12%) 원 배경, 크기 변화 없음 |

⚠️ 미선택 파스텔과 면의 대비는 1.12–1.27:1, 테두리(ink 28%)는 면 대비 라이트 1.83:1 · 다크 2.34:1로 WCAG 1.4.11의 3:1에 못 미친다. 근거: 색 자체가 본질적 정보이고 이름(캡션/Semantics)이 따로 있으며, **상태 신호(선택 링+체크)는 14:1 이상**이다. a11y 스펙이 엄격하면 테두리를 `pb.controlEdge`(ink 50%, 라이트 3.30:1)로 바꾸면 된다(토큰 한 줄, 대신 8개 원이 "그려진" 느낌이 강해진다). 결정 필요.

### 5.4 접근성 (Semantics)

- 격자 그룹: `Semantics(label: '노트 색', container: true)`, 각 스와치는 `Semantics(label: <이름>, button: true, selected: <선택>, inMutuallyExclusiveGroup: true)`. 라벨은 이름만(`로즈`, `자동`, `무지개`), "선택됨"은 `selected`가 말하게 한다.
- 영어: Auto, Rose, Peach, Butter, Lime, Mint, Aqua, Blue, Lilac, Rainbow.
- 터치 타깃 48×48, 좌우·상하 인접 셀이 겹치지 않음. 데스크톱 포인터에서도 같은 크기를 쓴다(`pbTarget`은 36이지만 한 컴포넌트가 두 크기를 갖지 않도록).
- 키보드: 탭으로 격자 진입, 방향키로 이동(`FocusTraversalGroup` + 기본 `DirectionalFocusIntent`), `Enter`/`Space` 적용, `Esc` 닫기.
- 툴팁(`Tooltip`)은 데스크톱 호버/포커스용 보조, 폰은 캡션이 같은 역할을 한다.
- `MediaQuery.highContrast`: 선택 링 3px(`PbFocusRing`과 같은 규칙).

### 5.5 모션 (최소)

| 대상 | 동작 | 시간 | 곡선 |
|---|---|---|---|
| 스와치 선택 링·체크 | 크로스페이드(크기 변화 없음) | `pbFast`(120ms) | `easeOut` |
| 카드/편집기 배경 | 단색→단색 `AnimatedContainer`/색 보간, 단색↔무지개는 `AnimatedSwitcher` 페이드 | 200ms | `easeOutCubic` |
| 시트·팝오버 열림 | M3 기본 | — | — |

`MediaQuery.disableAnimations`이면 전부 `Duration.zero`(`pbFast`가 이미 처리).

## 6. 반응형

| 폭 | 선택기 | 비고 |
|---|---|---|
| **<600** (폰) | 하단 시트, 격자 320 폭(가로 간격 20), 캡션 있음 | 편집기 헤더 팔레트 아이콘 44 타깃, 카드 ⋯ 메뉴 항목 |
| **600–1024** (태블릿) | 팝오버 288, 간격 4, 셀 48 | 터치 가능 → 48 셀 유지. 팝오버 폭이 화면 가장자리에 걸리면 `MenuAnchor` 정렬이 뒤집힘 |
| **>1024** (데스크톱) | 같은 팝오버 + 호버 툴팁 + 키보드 이동 | 가운데 패널이 좁아도(308–384px) 팝오버는 오버레이라 영향 없음 |

보드 카드·소스 행에서 무지개 카드는 `noteRainbow` 그라디언트, 그라디언트를 못 쓰는 곳은 `noteRainbowFlat`.

## 7. Flutter 구현 노트 (코드는 수정하지 않았다)

토큰(`Pb`에 추가 — `notes`는 그대로 5개):

```dart
final List<Color> notesExtra;    // [rose, aqua, lime]  idx 5..7
final List<Color> noteRainbow;   // 6 stops, 4.1 표 순서
final Color noteRainbowFlat;

// choice: null = auto, 0..7 solid, 8 rainbow
Color? noteSolid(int? choice, int? id) => choice == null
    ? notes[(id ?? 0) % notes.length]               // Auto: stays % 5
    : choice < notes.length ? notes[choice]
    : choice < notes.length + notesExtra.length ? notesExtra[choice - notes.length]
    : null;                                          // 8 → use noteRainbow
```

- 라이트·다크 값은 3.2 표를 그대로 `Pb.light`/`Pb.dark`에 넣는다. 다크 `notesExtra`는 `[0xFF472737, 0xFF073338, 0xFF333813]`, 라이트는 `[0xFFFFD7E9, 0xFFBDEDF2, 0xFFE4F0C5]`.
- **카드에 그라디언트를 넣을 때 함정**: 지금 `DocumentCard`는 `Card(color: ...)` + `InkWell`이다. `Card.color`는 그라디언트를 못 받고, `DecoratedBox`를 `InkWell` **위**에 두면 잉크(호버·눌림)가 가려진다. `Card(color: Colors.transparent)` 안에 **`Ink(decoration: BoxDecoration(gradient: ...))`** + `InkWell`을 쓴다(Material 위에 잉크가 그려져 호버가 보인다). `Clip.antiAlias` 유지.
- 서버/모델: `Document`(또는 노트)에 `noteColor: int?` 추가는 서버 스키마 작업이다(여기선 범위 밖). 알 수 없는 값(>8)은 자동으로 취급해 구버전과 호환.
- 격자: `Wrap`이 아니라 `Row` 두 줄(`MainAxisAlignment.spaceBetween` / 고정 간격)이 줄바꿈 위험이 없다. 스와치는 `Semantics` > `InkResponse`(원형, `radius: 24`) > `CustomPaint`/`DecoratedBox`.
- 다크 팔레트의 `A` 스와치 채움 `#2A2620`은 다크 시트 `#28222E`와 대비가 1.03:1이라 **테두리가 경계를 만든다**(라이트도 흰색 vs `#FFFDFB`).
- 에디터 배경에도 같은 색을 쓸지는 이 문서에서 정하지 않았다(⚠️ 클라이언트 확인): 카드 색과 편집기 면이 다르면 선택 결과가 보이지 않는다.

## 8. 확인한 것 / 못 한 것

- ✅ 계산: 8색×4 글자색 대비, 그라디언트 3,001점 최소값, 플랫 대비, ΔE, 스와치·테두리 대비.
- ✅ 코드로 확인: 기존 `notes` 값, `noteColor` 모듈로, `_pickScope` 분기, `PbFocusRing` 규격, `sign_in_screen`이 `notes[0]` 사용, 출처 행이 노트 색을 쓰지 않음.
- ⚠️ 눈 확인 필요: 다크 팔레트(특히 아쿠아 `#073338`, 라임 `#333813`)의 색감, 다크 무지개 카드가 탁해 보이는 정도(시안에서는 올리브 기가 도는 갈색 띠로 보임), 라이트 아쿠아 `#BDEDF2`가 다른 파스텔보다 살짝 진한지.
- ⚠️ 스와치의 스윕 그라디언트는 SVG에서 90개 쐐기로 근사해 그렸다(실제 Flutter `SweepGradient`는 부드럽다).
- ⚠️ 눌림 오버레이(ink 12%)를 얹으면 AA가 깨지는 곳이 기존 팔레트에도 있다(다크 버터 위 inkMuted 3.35, 라이트 피치 위 warnText 4.37). 일시적 상태라 이 문서는 고치지 않았다.
- 실제 앱·실기기에서 렌더하지 않았다. 시안은 SVG(손으로 작성, 글꼴 Pretendard / 세리프는 Georgia 대체)이며 Fraunces·Noto Serif KR과 글자 폭이 다르다.
