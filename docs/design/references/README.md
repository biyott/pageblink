조사일 2026-10-14. 대상: Keep 스타일 마크다운 노트 + PDF, "내 노트에 질문하기" AI 패널과 ⚡ 출처 인용, 데스크톱 웹 + 모바일 앱. 방향은 `../ab-glass-paper/spec.md`(AB Glass Paper: 라벤더→피치 그라데이션, 프로스티드 셸, 파스텔 노트 카드, 세리프 제목, 바이올렛 포인트).

## 사용 조건 (중요)

- 이 폴더의 이미지는 **영감용 참고 자료**다. 각 작가의 저작물이며 PageBlink 앱/문서/데모에 **그대로 넣거나 변형해 쓰지 않는다**. 에셋(일러스트, 로고, 3D, 사진, 아이콘)은 가져오지 않고, 아래 "가져올 점"의 **구조와 수치 아이디어**만 쓴다.
- 이미지는 Dribbble CDN 미리보기(가로 1400px JPEG)다. 외부 링크가 사라져도 보관용으로만 둔다. 공개 저장소/제출물에 포함하기 전에 용량·저작권을 다시 판단하고, 필요하면 이 폴더를 `.gitignore` 처리한다.
- 수치(px, 비율)는 1400px 미리보기에서 **눈대중으로 잰 값**이다. 구현 기준은 `../ab-glass-paper/spec.md`의 토큰이며, 아래 "적용 가이드"는 그 토큰을 **확인·보강**하는 용도다.
- 조사 경로: Dribbble 검색/태그/작가 페이지(원문 접근은 봇 차단으로 불안정해, 공개 리더 프록시로 목록·메타를 읽고 CDN 미리보기를 내려받음). 모든 이미지는 `Read`로 직접 열어 확인했다. 게시일은 대부분 페이지에 노출되지 않아 **Dribbble 게시 ID 기준 2025~2026 추정**이다(ref-13만 2025-09-10으로 확인). Behance(403), Land-book(403)은 막혀서 쓰지 못했다.

- Recall(neo-brutal 노랑/검정), Reflect(다크 블랙홀 히어로), 다크 오렌지 오브 AI 노트, Notiva(다크 블루 유리) 등은 톤이 달라 제외했다. 다만 Reflect와 Notiva가 "차가운 다크 유리"의 전형이라 **다크 모드를 차갑게 만들지 말 것**(ab-glass-paper 다크는 딥 플럼/웜 브라운)의 반면교사로 삼는다.

# 적용 가이드 — AB Glass Paper 구현 규칙 (14개)

`../ab-glass-paper/spec.md`가 토큰의 기준이다. 아래는 레퍼런스에서 확인한 **구체 값과 추가 규칙**이며, 스펙과 충돌하면 스펙이 우선한다. (스펙 값을 재확인한 항목은 "확인", 새로 제안한 항목은 "추가"로 표시.)

1. **배경 그라데이션은 전면 단색 채움이 아니라 "구석 글로우 + 아주 옅은 중간"** (추가, ref 06, 09, 12). 루트 그라데이션 `#EDE6FA → #F7E8EE → #FFE9DC`(스펙) 위에 `#CDBBFA` 45% 블러 원(지름 ≈ 화면 높이의 60%, 좌상단 밖으로 반쯤)과 `#FFC9A8` 45% 원(우하단)을 고정한다. 본문 읽기 영역(노트 편집, 긴 답변)은 배경 위 흰 80%+ 면을 쓰고 글로우가 글자 뒤로 오지 않게 한다. 대비는 `ink #1F1B16`로 항상 13:1 이상.

2. **유리 셸은 불투명도로 계층을 만든다** (확인 + 추가, ref 07, 08, 14). 사이드바 `#FFFFFF` 62% < Ask 패널 62% < 입력창/답변 카드 74%(스펙). 데스크톱 외곽 프레임은 `radius 28`, 패널 24(스펙), 카드 16(스펙). 블러는 `sigma 18`(스펙), 테두리 1px `#FFFFFF` 80%, 그림자 `#6C4CF5` 10% blur 24 y 8. 따뜻한 배경에서 유리가 차가워 보이면 흰 불투명도를 74~85%로 올린다(ref 07은 85~90%).

3. **데스크톱 3열 치수** (확인 + 추가, ref 05, 08, 17, 20). 사이드바 폭 **240**, 보드 가변(최대 1100), Ask 패널 **360~400**(기본 380), 패널 사이 gap **24**, 바깥 여백 **24~32**(스펙). 태블릿은 아이콘 레일 **72**(ref 08은 96, ref 05/20은 56 → 56~72 허용) + 라벨은 툴팁. 사이드바 항목 높이 **40**, 활성은 풀폭 pill(`accent` 채움, 스펙) 또는 ref 16처럼 연회색 풀폭 pill 중 하나로 통일(바이올렛 한정 규칙상 채움 pill).

4. **타입 스케일** (확인 + 추가, ref 04, 10, 11, 18). 화면 제목 **Fraunces 28/600**(데스크톱 32, 스펙) · 노트 상세 제목 **28/600, letterSpacing -0.3** · 빈 상태 헤드라인 **세리프 32(모바일 28) / 1.2** · 카드 제목 **18/600/1.25** · 본문 **Inter 16/1.5**, 답변 **15/1.55** · 라벨 **13/500** · 섹션 소형 라벨 **대문자 11~12px, letterSpacing +0.8, `inkMuted`**(ref 07, 09). 한 화면에서 세리프는 제목/브랜드/인용 큰 문구에만 쓰고 본문과 UI 라벨에는 쓰지 않는다.

5. **노트 카드: 단색 파스텔 + 헤어라인, 유리 금지, 그림자는 거의 없음** (확인, ref 04, 09, 10). `radius 16`, 패딩 16, 1px `noteBorder`, 그림자 `ink 6% blur 8 y 2`(스펙). 카드 안 "종류 아이콘" 타일은 가로·세로 32, radius 10, 카드색보다 한 단계 진한 틴트(ref 04의 아이콘 타일). 카드 상단 메타는 `종류 · 날짜`(예: `PDF · 12 pages`, 노트는 `Note · Mar 12`)를 `inkMuted` 12px로.

6. **빈 상태(Ask) 레이아웃** (추가, ref 18, 03, 05, 17). 위에서 아래로: ⚡ 로고(32) → 세리프 헤드라인 "내 노트에 무엇이든 물어보세요" → 신뢰 서브카피 "모든 답변은 ⚡ 출처로 연결됩니다"(14, `inkMuted`) → 제안 카드 **데스크톱 4열 / 모바일 2열 가로 스크롤**(카드 높이 ≈ 112, radius 16, `glassFillStrong`, 아이콘 타일 32 + 제목 14/600 + 설명 12 두 줄) → 입력창. 패널 하단에 면책 한 줄 "AI는 틀릴 수 있어요. 출처를 확인하세요."(12, `inkMuted`). 제안 문구는 사용자 데이터에서 동적으로 만들고(`최근 노트: 회의록…`), 없으면 일반 예시.

7. **입력창(Composer) 구조** (추가, ref 17, 20, 01, 12). 높이 모바일 **52**, 데스크톱 **56**(여러 줄 시 최대 5줄 후 스크롤). 구성 순서: 상단 행 = 스코프 칩(`My notes`, `Project: …`, `+ Scope`), 입력 영역, 하단 행 = 첨부 `+`(PDF 업로드) · 모델 pill `Gemma 4 26B · free ▾` · 원형 전송 **40×40** `accentGradient`. 비활성(빈 입력) 전송은 `hairline` 색 + 아이콘 `inkMuted`. 포커스 시 **하단 테두리에만 바이올렛 글로우**(`accent` 35%, blur 16, 높이 2, ref 20) 120ms 페이드. 마이크 버튼은 두지 않는다(스펙).

8. **답변 말풍선과 인용 위계** (확인 + 추가, ref 01, 03, 04, 16, 19). 질문: 우측, `accentGradient`, 흰 글자, radius 18(우하단 6), 최대 폭 80%(스펙). 답변: **말풍선이 아니라 좌측 정렬 카드**(`glassFillStrong` + `glassBorder`, radius 18/좌상단 6, 최대 폭 92%, 패딩 16). 답변 카드 구조를 고정한다: 본문(Inter 15/1.55, 인라인 `⚡n`) → 구분선(`hairline`) → `Sources` 라벨(12, 대문자, `inkMuted`) → 칩 행 → 액션 행(복사 · 다시 생성 · 👍 아이콘 20, `inkMuted`). 한 답변의 인용은 **최대 5개 칩 + `+N`**, 같은 노트의 여러 구절은 하나의 칩으로 합치고 `p.4, p.7`로 표시.

9. **인용 칩(⚡) 스타일** (확인 + 추가, ref 01, 03, 04, 16). 인라인 `⚡n`: 높이 18, 가로 패딩 6, radius 999, `accentContainer` 배경, `accent` 번개 12 + 숫자 12/600, 본문 텍스트 baseline에 맞춤, 탭 영역은 최소 32×32로 확장. 하단 칩(`ActionChip`): 높이 **32**, 1px `accent` 테두리, 글자 `onAccentContainer` 13/500, 내용 `⚡1 · Budget memo`, PDF는 `⚡2 · Spec.pdf p.4`. 모바일에서 칩이 3개를 넘으면 ref 04처럼 **리스트 행**(종류 아이콘 타일 32 + 제목 14/600 + `종류 · 날짜` 12 + 쉐브론, 높이 56)으로 전환해 가독성을 확보한다. 칩 색을 노트 색에 맞추지 말고 항상 바이올렛으로 통일한다.

10. **출처로 "blink" 이동 (뷰어/하이라이트)** (확인 + 추가, ref 01, 14, 16). 모바일은 바텀시트(높이 화면의 62%, radius 24, 드래그 핸들 36×4)에 `Cited in AI answer · Source 1 of 3` + 쪽 선택 + 본문 + 구절 하이라이트(`accent` 18%, 모서리 4)와 `Open full page` 버튼. 데스크톱은 스펙대로 보드 위 오버레이 미리보기(최대 폭 440)로 열고 Ask 패널은 그대로 유지한다. 카드 링 펄스 0.6s(스펙), 키보드 `Esc` 닫기를 힌트로 노출(ref 16). 하이라이트가 없는 노트(마크다운 전체 인용)는 해당 단락만 스크롤 + 배경 `accentContainer` 1.2s 페이드.

11. **PDF 업로드 시트와 색인 진행** (추가, ref 13, 01, 06). `Add PDF` 시트: 점선(`hairline` dashed 1.5, radius 16, 높이 140) 드롭 영역 + "PDF 선택" 버튼 + 하단 티어 선택(Cloak / My cloud / Hackathon 라디오 3행). 업로드 후 카드에 **단계 체크리스트**: `업로드 → 텍스트 추출 → 임베딩 → 준비됨`(각 행 24, 완료 체크 `success`, 진행 중 `LinearProgressIndicator` `accent`). 실패는 스펙의 앰버 행 + `Keyword search only`. 일치도가 있는 검색 결과에는 ref 06처럼 **얇은 바(폭 60, 높이 4)** 를 써도 된다.

12. **모바일 레이아웃** (확인 + 추가, ref 04, 12, 02). 헤더: 소형 인사 라벨(`Good morning`, 14 `inkMuted`) + 세리프 대제목(28). 헤더 바로 아래 **Ask 진입 pill**(높이 48, 유리, 힌트 "내 노트에 물어보기", 우측 번개 원형 버튼)을 노트 보드 상단에 항상 보인다(ref 12 — 탭 전환 없이 진입). 보드는 2열 masonry gap 12, 좌우 16(스펙). 하단 내비 3탭 + 우측 FAB(스펙). 컬렉션 타일(ref 04)은 선택 기능으로, 쓴다면 높이 88, 2열, 파스텔 6색 매핑은 노트 색 인덱스와 같은 팔레트를 재사용한다.

13. **모션** (추가, ref 01, 13, 20). 기본 이징 `Curves.easeOutCubic`, 길이: 탭 피드백 80ms · 칩/패널 상태 160ms · 시트/패널 열기 280ms · 페이지 전환 220ms. 답변 생성 중: 단계 로그 줄이 순서대로 **120ms 간격**으로 나타나며(ref 20), 본문은 토큰 스트리밍(애니메이션 추가 없이 텍스트 증가) + 끝에서 ⚡n pill이 **scale 0.9→1.0, 160ms**로 등장. 입력창 글로우, 링 펄스는 `MediaQuery.disableAnimations`이면 생략(스펙). 카드 호버는 `y 6, blur 16, ink 10%`(스펙)이며 translate는 쓰지 않는다(masonry 재배치 방지).

14. **섹션 헤더와 소형 라벨 규칙, 바이올렛 사용처 한정** (추가 + 확인, ref 07, 09, 15, 16). 보드 섹션(`Pinned`, `Recent`, `PDFs`)은 소형 대문자 라벨 11/600 +0.8 + 우측 원형 `+` 또는 `See all`. 활성 탭 pill은 `accentContainer`(ref 15, 연보라). 바이올렛은 ⚡ 인용 · 기본 버튼 · 활성 내비 · 사용자 말풍선 · 포커스 글로우로만 쓴다. 한 화면에서 "그라데이션 면"은 **최대 1개**(New note FAB 또는 사용자 말풍선, ref 09의 "한 칸만 그라데이션" 원칙). 앰버는 색인 실패에서만(스펙).

## 이 레퍼런스에서 하지 말 것

- 일러스트/3D/마스코트(ref 01 로봇, 13 Otto, 10 Recall 계열)와 브랜드 이름·로고·카피를 그대로 쓰지 않는다.
- 파랑·청록·초록 중심의 포인트 색(ref 01, 08, 16, 18)은 구조만 보고 색은 바이올렛으로 치환한다.
- 유리를 노트 카드까지 확장하지 않는다(성능 + 가독성, 스펙). ref 02, 07의 반투명 카드는 셸/보조 표면에만 해당한다.
