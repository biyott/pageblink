### 1-2. 수상작에서 반복되는 패턴

- **독창성보다 실행력**: 심사위원은 "세상에 없던 것"보다 **작동하는 완성품**을 뽑는다. "Y한 사람들을 위한 더 나은 X"가 "아무도 안 만든 것"보다 강한 프레임이다.
- **개인이 겪는 문제에서 출발**: 피치가 선명해지고 무엇을 만들지 분명해진다.
- **한 가지 기능에 스코프 집중**: 12시간짜리 소박한 프로젝트(습관 트래커 등)가 데모가 깨진 야심작을 이긴 사례가 반복 보고됨.
- **스폰서 기술의 깊은 활용**: Supabase 해커톤 수상작들은 Storage 동기화(공동 시청 앱 Fireplace), Realtime 등 주최사 기능을 '창의적으로' 썼다. **이번 해커톤에서는 Serverpod 기능을 얼마나 깊게 쓰느냐가 그 역할.**
- **AI 사용 자체는 차별점이 아님**: 개발자 97%가 이미 AI 도구를 쓴다. "챗봇 붙였어요"는 기본값이지 가산점이 아니다.
- **데모·README에 시간 투자**: 코딩을 일찍 멈추고 피치를 2시간 이상 리허설한 팀이 코드가 더 좋은 팀을 이긴다.

### 1-3. Serverpod가 제공하는 무기 (주제 선정의 재료)

주제는 아래 기능을 **자연스럽게 2~3개 이상** 쓰게 되는 것이 유리합니다 (심사 25%가 "스택 활용도").

| 기능                             | 내용                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| **실시간 스트리밍**              | WebSocket 연결 관리 없이 Dart 객체를 스트림으로 푸시 — 채팅, 게임, 라이브 대시보드에 적합 |
| **Future Calls (작업 스케줄링)** | cron 대체. 지정 시간·지연 후 메서드 실행, **서버 재시작에도 유지** |
| **ORM + 마이그레이션**           | Dart-first 타입세이프 ORM, 관계·마이그레이션 지원            |
| **인증**                         | Google/Apple/Firebase/이메일 로그인 내장                     |
| **파일 업로드**                  | S3, GCS, 또는 PostgreSQL에 직접 저장                         |
| **캐싱**                         | 인메모리/Redis 분산 캐시                                     |
| **웹 서버 (Relic)**              | 내장 고성능 웹 서버 → **웹 개발자인 당신의 강점을 살릴 수 있는 지점** |
| **Serverpod Cloud 배포**         | 명령어 한 줄 배포 (상금의 절반이 Cloud 크레딧 = 주최사가 밀고 있는 기능) |

## 3. 주제 평가 프레임

각 주제는 아래 5개 축으로 평가했습니다 (★ 1~5).

- **작동 실현성**: 3주 내 1인/소팀으로 E2E 완성 가능한가

#### 1. 🎯 플래닝 포커 / 스프린트 견적 툴

`[🔴⏰🔐🗄️🌐]`

- **개요**: 개발팀이 스토리 포인트를 실시간 투표로 정하는 도구. 방 생성 → 링크 공유 → 동시 카드 공개 → 히스토리 저장.
- **선정 이유**: 방·투표·공개 타이밍이 전부 실시간 스트림. 개발자 심사위원이 실제로 쓰는 도구라 유용성 설득이 쉬움. 스코프가 작아 완성도를 높일 시간이 남는다.
- **특징/차별화**: 웹(Relic/Flutter Web)으로 참가자는 설치 없이 접속, 호스트만 앱 사용 — 웹+Flutter 역량을 모두 보여주는 구성.
- **리스크**: 유사 서비스 다수 → "비동기 원격팀용 투표 마감 타이머(Future Calls)" 같은 비틀기 필요.
- 작동 ★★★★★ · SP활용 ★★★★☆ · 데모 ★★★★☆ · 유용성 ★★★★☆ · 차별화 ★★★☆☆

#### 2. 🧑‍🍳 실시간 공동 장보기·집안일 보드

`[🔴🔐🗄️⏰]`

- **개요**: 가족/룸메이트가 공유하는 장보기 리스트 + 집안일 로테이션. 한 명이 체크하면 전원 화면에 즉시 반영, 담당 로테이션은 Future Calls로 매주 자동 갱신.
- **선정 이유**: 참가자 팀들도 가족 그룹 앱을 만들고 있을 만큼(조사에서 확인) 이 해커톤과 궁합이 좋은 도메인. 실시간+스케줄링 조합이 자연스럽다.
- **특징**: "내가 매일 겪는 문제" 스토리텔링이 강력. 마트에서 실제로 쓰는 데모 촬영 가능.
- **리스크**: 흔한 아이디어 → 완성도로 승부해야 함.

#### 9. 🗣️ 회의 녹음 → 액션아이템 자동 배분

`[📁⏰🔴🗄️🔐]`

- **개요**: 회의 오디오 업로드 → 서버가 STT+요약(백그라운드 Future Call) → 액션아이템을 팀원별로 배분 → 마감 전 리마인더 자동 발송.
- **선정 이유**: 멀티모달(음성) 트렌드 + Future Calls의 "나중에 실행" 특성이 완벽하게 맞물림. 업로드 즉시가 아닌 백그라운드 처리 구조 자체가 스택 이해도를 증명.
- **특징**: 처리 진행률을 실시간 스트림으로 보여주면 데모가 살아남.
- **리스크**: STT API 비용/시간 → 3분 이하 클립으로 데모 설계.

- **선정 이유**: 사회적 임팩트(수상 가점 영역) + 사진 중심이라 데모가 예쁨. 실제 보호소 1곳과 협의만 돼도 "Real"의 끝판왕 스토리.
- 작동 ★★★★☆ · SP활용 ★★★★☆ · 데모 ★★★★☆ · 유용성 ★★★★★ · 차별화 ★★★★☆

#### 30. 🧯 우리 동네 재난·정전 상황판

`[🔴🗄️🌐⏰⚡]`

- **개요**: 주민이 정전·단수·통제 상황을 제보하면 지도를 함께 쓰는 실시간 상황판. 해제 예상 시간 카운트다운, 공공 API 주기 수집(Future Calls).
- **선정 이유**: 재난 대응은 다중 에이전트 홍수 경보 등 2026 수상작이 나온 검증 도메인. 웹 공개 상황판(로그인 불필요) + 제보 앱의 이원 구성이 웹+앱 역량을 모두 증명.
- **리스크**: 데모 시나리오를 위해 시뮬레이션 데이터 준비 필요.
- 작동 ★★★☆☆ · SP활용 ★★★★★ · 데모 ★★★★☆ · 유용성 ★★★★★ · 차별화 ★★★★☆

| 🥇    | **#11 에이전트 작업 큐 대시보드** | 에이전트 AI 트렌드 × Future Calls 고유 기능의 유일무이한 교차점. "서버에 사는 에이전트"는 이 해커톤의 정체성과 공명하고 겹칠 확률도 낮다 |
| 🥈    | **#15 업타임 모니터**             | 가장 확실하게 **완성**되는 주제. 작동 30% + 개발자 유용성 20%를 안전하게 확보하고, Relic 웹 상태 페이지로 웹 역량까지 |
| 🥉    | **#9 회의 녹음 → 액션아이템**     | 멀티모달 + 백그라운드 처리 + 리마인더까지 SP 기능 총동원. 데모 임팩트 최상 (단, STT 파이프라인 1주차 검증 필수) |
| 4    | **#22 동네 공구 매니저**          | 실시간 카운터 + 자동 마감의 드라마틱한 데모. 한국적 소재로 차별화 |
| 5    | **#8 문서 RAG 비서**              | 트렌드 1순위 카테고리를 SP 파일업로드+DB로 정면 구현. pgvector 확장이 기술 창의성 카드 |
